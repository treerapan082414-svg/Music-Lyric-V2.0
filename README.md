# BK LYRIC STUDIO PRO 1.1

เว็บสร้าง lyric video แบบ Local First ภาษาไทย: เพลงและเนื้อร้องประมวลผลในเบราว์เซอร์ ไม่มีบัญชีผู้ใช้หรือบริการ AI ภายนอก

## รันและตรวจสอบ

ใช้ Node.js 24 และ npm ตาม package-lock.json

```sh
ONNXRUNTIME_NODE_INSTALL_CUDA=skip npm ci
npm run dev
npm test
npm run build
```

ทดสอบเบราว์เซอร์ด้วย `npm run test:e2e` ต้องมี Chromium (`CHROMIUM_PATH` หรือ `/usr/bin/chromium`) และ ffmpeg/ffprobe ชุดทดสอบสร้างเสียงสังเคราะห์จริง อัปโหลด MP3/WAV ทดสอบการแก้ไข/บันทึก แล้วส่งออกและถอดรหัส WebM ทั้ง 16:9 และ 9:16

## วิธีใช้งาน

1. เลือกเพลง MP3/WAV/M4A/FLAC/OGG/AAC ที่เบราว์เซอร์อ่านได้ (ไม่เกิน 150 MB)
2. วางเนื้อเพลงหนึ่งบรรทัดต่อหนึ่งท่อน ใช้ `[Verse]`, `[Chorus]` ระบุโครงสร้าง หรือนำเข้า TXT/LRC/SRT/VTT การนำเข้าแทนที่เนื้อเพลงปัจจุบัน และ Undo ได้
3. เลือกท่อน เล่นเพลง กด `I` ตอนเริ่มร้อง และ `O` ตอนจบ หรือแก้ช่องวินาทีได้สามตำแหน่งทศนิยม ลากบล็อกเพื่อย้ายเวลา ลากขอบเพื่อปรับความยาว คลิก waveform เพื่อข้ามตำแหน่ง
4. เปิดโหมดจับเวลาทีละท่อนแล้วกด Space ทุกครั้งที่เริ่มบรรทัดถัดไป ในโหมดนี้ใช้ปุ่มเล่น/หยุดแทน Space จับ OUT ของท่อนสุดท้ายด้วยตนเอง
5. กด **ตรวจคำที่ร้องให้ตรงเนื้อเพลง** → เลือกภาษาและโมเดล → **ฟังเสียงและเทียบคำร้อง** ตรวจผลแต่ละท่อนก่อนใช้เวลา ดูรายละเอียดด้านล่าง แท็บวิเคราะห์ยังมีโครงสร้าง บรรทัดซ้ำ และตรวจเวลา
6. เลือกธีม สี ขนาด ตำแหน่งข้อความ และสัดส่วนวิดีโอ ภาพและตัวแสดงเสียงใช้ Canvas/Web Audio จริง
7. ส่งออก WebM 720p 30fps พร้อมเสียง ใช้เวลาประมาณความยาวเพลง เก็บแท็บไว้ด้านหน้า ปิดโหมดประหยัดพลังงาน และตรวจวิดีโอก่อนเผยแพร่

## ความตรงของเนื้อร้อง

ระบบใหม่ใช้ `@huggingface/transformers` 3.8.1 และ `onnx-community/whisper-{tiny,base,small}_timestamped` (q8, CPU/WASM) เพื่อถอดเสียงจริงพร้อม word/token timestamps จาก cross-attention แล้วจับคู่กับเนื้อเพลงตามลำดับด้วย dynamic programming ระดับตัวอักษร ไม่แก้เนื้อเพลงต้นฉบับ ใช้การตัดคำไทยของ Intl.Segmenter และคงสระ/วรรณยุกต์ไว้

1. เพิ่มเพลงและเนื้อเพลง แล้วเปิด **ตรวจคำที่ร้องให้ตรงเนื้อเพลง**
2. เลือกภาษาและโมเดล tiny เบา / base สมดุล / small ใหญ่ขึ้น ใช้ RAM และเวลามากขึ้น ครั้งแรกโหลดโมเดลหลายสิบถึงหลายร้อย MB จาก Hugging Face ครั้งถัดไปเบราว์เซอร์อาจใช้แคชได้
3. ถ้ามีแทร็ก Vocals ที่แยกจากเพลง ให้เลือกเพิ่มเพื่อช่วยลดดนตรีรบกวน ต้องคงเวลาเดิมและช่วงเงียบไว้ ความยาวต่างจากเพลงเกิน 1 วินาทีจะถูกปฏิเสธ ระบบไม่แยกเสียงร้องให้เอง
4. กด **ฟังเสียงและเทียบคำร้อง** รอผลใน Web Worker ยกเลิกได้ เพลงไม่ถูกอัปโหลดไปเซิร์ฟเวอร์ ขณะนี้จำกัดครั้งละ 10 นาที และการเทียบตัวอักษรมีเพดานขนาดเพื่อป้องกัน RAM ล้น
5. ผลเป็นข้อเสนอ ไม่ใช้เวลาแทนเดิมอัตโนมัติ คลิกท่อนเพื่อดู **เนื้อเพลง / ได้ยิน** คำสีเขียวคือตัวอักษรตรง สีเหลืองใกล้เคียง สีแดงหาไม่พบ คำที่หาไม่พบไม่มีการแต่งเวลาให้
6. คลิกแต่ละคำ ฟังเฉพาะคำ แก้ IN/OUT หรือจับเวลาด้วยตนเอง แล้วกด **ใช้เวลารายคำกับท่อนนี้** ปุ่ม **ใช้เวลาท่อนที่ตรงชัดเจน** ใช้ได้เฉพาะท่อนที่ทุกคำตรงและไม่มีเวลาร่วม/ช่วงที่ผิดปกติ
7. เมื่อใช้เวลาแล้ว Preview และ Export จะไฮไลต์ตามเวลาแต่ละคำจาก renderer เดียวกัน รายละเอียดคำบันทึกใน IndexedDB/JSON การแก้เนื้อเพลงจะล้างการจับคู่เก่า การย้ายบล็อกและ offset ย้ายเวลาคำพร้อมกัน การเปลี่ยนเพลงใช้ SHA-256 ตรวจว่าเป็นไฟล์เดิมก่อนคงผลไว้

โมเดลอาจคืนมาหลายอักษรในช่วงเดียวกัน หรือให้สระ/วรรณยุกต์เป็น token ระยะศูนย์ ระบบรวมอักษรกับช่วงเวลาข้างเคียงและทำเครื่องหมายว่าเป็นเวลาร่วม (`≈`) ไม่แบ่งเวลาเท่า ๆ กันแล้วอ้างว่าเป็นเวลาที่วัดได้

**ยังไม่ใช่ Forced Alignment และไม่รับประกันตรง 100%** ASR อาจฟังผิดหรือสร้างคำที่ไม่มีจริง โดยเฉพาะเพลงไทย เสียงร้องยาว RAP และดนตรีหนา “ตรงอักษร” วัดการจับคู่ข้อความที่ถอดได้ ไม่ใช่ความเชื่อมั่นทางเสียง และไม่ได้ยืนยันว่า timestamp ตรงทุกคำ ความละเอียดช่องเวลา 1 ms ไม่เท่ากับความแม่นยำของโมเดลหรือเฟรมวิดีโอ (30fps ≈ 33 ms/เฟรม)

วิธีเดิมที่แบ่งเวลาจากพลังงานเสียงย้ายไปอยู่ในเครื่องมือพับ **แบ่งเวลาคร่าว ๆ (ไม่เทียบคำร้อง)** เวลาประเภทนี้แสดงชัดว่ายังไม่เทียบกับเสียงร้อง

สามารถนำเข้า JSON จากผลถอดเสียงภายนอกได้ (ไม่เรียกโมเดลในโหมดนำเข้า):

```json
{"words":[{"word":"hello","start":1.23,"end":1.8},{"word":"world","start":2.1,"end":2.6}]}
```

รองรับ `segments[].words[]` ของ Whisper และ `chunks[{text,timestamp:[start,end]}]` ด้วย เวลาเป็นวินาที ต้องเรียงลำดับและไม่เกินเพลง การนำเข้าไฟล์นี้หมายถึงนำเข้าผลที่มีอยู่ ไม่ใช่หลักฐานว่าเว็บได้ถอดเสียงใหม่

LRC ไม่มีเวลาจบจึงใช้เวลาเริ่มท่อนถัดไปเป็นจุดจบ ท่อนสุดท้ายใช้ความยาวเพลง เมื่ออ่านโดยยังไม่ได้แนบเพลง เวลาอาจต้องปรับใหม่หลังเพิ่มเพลง LRC export เก็บเฉพาะเวลาเริ่มตามรูปแบบไฟล์ ไม่เก็บ OUT ที่แก้เอง ใช้ JSON เพื่อเก็บ IN/OUT ครบถ้วน

## บันทึกโปรเจกต์

- IndexedDB บันทึกโปรเจกต์และไฟล์เสียงในเบราว์เซอร์อัตโนมัติหลังแก้ไขประมาณ 800 ms ต้องไม่ล้างข้อมูลเว็บไซต์
- ดาวน์โหลด JSON เป็นสำรองได้ แต่ JSON **ไม่รวมไฟล์เพลง** เมื่อเปิด JSON หรือย้ายเครื่องต้องแนบเพลงเดิมอีกครั้ง
- สำรอง JSON และไฟล์เสียงก่อนสร้างโปรเจกต์ใหม่ เปลี่ยนเบราว์เซอร์ หรือเปลี่ยนโดเมน ข้อมูล IndexedDB ไม่ย้ายข้ามโดเมน
- Undo/Redo ใช้กับข้อความ เวลา และสไตล์ ไม่รวมการเปลี่ยนไฟล์เพลง การเปลี่ยนเพลง/เปิด JSON/สร้างโปรเจกต์ใหม่จะเริ่มประวัติใหม่
- ปุ่มความดังควบคุมเฉพาะการฟังตัวอย่าง ไฟล์ส่งออกใช้ระดับเสียงต้นฉบับ

## เผยแพร่ GitHub Pages

มี `.github/workflows/pages.yml` สำหรับ build/test/deploy เมื่อ push ไป `main`

1. push ซอร์สโค้ดและ package-lock.json ไป repository นี้
2. Settings → Pages → Source เลือก **GitHub Actions**
3. ดู Actions → Deploy BK Lyric Studio to Pages จนสำเร็จ
4. เปิด URL ที่ขั้นตอน Deploy คืนค่าให้ และทดสอบจากเว็บจริง

Vite ใช้ base `./` รองรับ subpath ของ GitHub Pages ไม่มี API key ที่ต้องฝังใน frontend และไม่มี backend ที่ต้องติดตั้ง

## ขอบเขตรุ่น 1.1

ทำแล้ว: ถอดเสียง Whisper ใน Web Worker, ตรวจตัวอักษรกับคำร้อง, เวลารายคำ/ฟังเฉพาะคำ/จับ IN-OUT คำ, karaoke highlight, นำเข้าผลถอดเสียง JSON, optional vocal stem, Editor, MP3/WAV และ codec ตามเบราว์เซอร์, RMS/peak waveform, นำเข้าเนื้อเพลง, timeline ย้าย/ปรับขอบ, IN/OUT, offset ทั้งเพลง, undo/redo, ตรวจโครงสร้างและเวลา, เสนอเวลาที่ระบุว่าเป็นค่าประมาณ, Canvas preview, 4 ธีม, spectrum จากเสียงจริง, 4 สัดส่วน, WebM พร้อมเสียงและระยะเวลา, ยกเลิก export, ตัวอย่างไฟล์สุดท้าย, autosave IndexedDB, JSON, LRC export, responsive UI, keyboard help

ยังไม่มี: Forced Alignment โดยเฉพาะ/โมเดลแยกเสียงร้อง, แปลภาษา, ฉากหลังภาพหรือวิดีโอนำเข้า, หลายแทร็ก, safe-zone/ลากข้อความใน preview, trim/fade, 30 animations/25 themes/9 visualizers, เอฟเฟกต์ WebGL/3D, MP4, 1080p/4K, export เร็วกว่าความยาวเพลง, PWA, recent projects หลายโปรเจกต์, project archive รวมสื่อ ไม่อ้างว่าครบทุก Phase ตามข้อกำหนดต้นฉบับ

แนะนำ Chrome/Edge บน desktop; codec, autoplay, IndexedDB และ MediaRecorder แตกต่างกันตามอุปกรณ์ การเปลี่ยนแท็บทำให้การวาดเฟรมถูกจำกัด ไม่ควร export ใน background เสียงยาวหรือไฟล์ใหญ่ใช้ RAM มาก การทดสอบ browser อัตโนมัติใช้เสียงสังเคราะห์และนำเข้า timestamp fixture สำหรับทดสอบการเชื่อมต่อแต่ละส่วน แยกจากการทดสอบโมเดลจริงด้วยเสียงพูดอังกฤษ/ไทย ผลเหล่านี้ไม่ใช่หลักฐานความแม่นยำเสียงร้องจริงทุกภาษา

## โครงสร้าง

- `src/App.tsx` — editor และการควบคุม
- `src/model.ts` — parser, timing, วิเคราะห์เนื้อเพลง, ตรวจ JSON
- `src/audio.ts` — decode และ RMS/peak
- `src/render.ts` — Canvas ที่ preview/export ใช้ร่วมกัน และ MediaRecorder
- `src/storage.ts` — IndexedDB และดาวน์โหลด
- `src/alignment.ts` — จับคู่ตัวอักษร/คำ ตรวจและย้ายเวลารายคำ
- `src/asr.worker.ts` — ถอดเสียง Whisper และจับคู่ใน Worker
- `src/SyncPanel.tsx` — หน้าตรวจคำร้องและแก้เวลารายคำ
- `scripts/prepare-runtime.mjs` — คัดลอก ONNX WASM ที่ได้รับผ่าน npm ไปเสิร์ฟจากโดเมนเดียวกับเว็บ
- `tests/` — unit และ browser integration
